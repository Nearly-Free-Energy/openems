= SRNE ESS

Provides read-only integration of an SRNE hybrid inverter with OpenEMS Edge.

== Overview

The bundle reads ESS telemetry from an SRNE inverter over Modbus RTU. It maps
the validated battery, grid-input and backup-output registers to the standard
OpenEMS `SymmetricEss`, `HybridEss` and `ElectricityMeter` channels.
The battery-inverter component also derives the OpenEMS grid/off-grid
lifecycle from machine-state register `0x0210`.

== Supported Devices

* SRNE ASP48120SH3
* Modbus RTU, holding-register reads (FC03), default Unit-ID `1`
* Validated at `9600 8N1`

[[_srne_ess]]

=== SRNE ESS

*Name*: SRNE ESS

*Factory-PID*: `Srne.Ess`

.Implemented Natures/Interfaces
* SymmetricEss
* HybridEss
* ModbusComponent

*Description*: Reads state of charge, battery voltage and current. Active power
and DC battery power are calculated from signed battery voltage and current.
Control-register writes are not part of this component.

.*Configuration*:
* `id` (String): Unique component ID (default: `ess0`)
* `alias` (String): Human-readable component name
* `enabled` (boolean): Enables the component (default: `true`)
* `modbus_id` (String): Modbus bridge component ID (default: `modbus0`)
* `modbusUnitId` (int): Device Unit-ID (default: `1`)
* `capacity` (int): Usable battery capacity in Wh (default: `0`)
* `maxApparentPower` (int): Maximum inverter apparent power in VA (default: `12000`)

[[_srne_battery_inverter]]

=== SRNE Battery-Inverter

*Name*: SRNE Battery-Inverter

*Factory-PID*: `Srne.BatteryInverter`

.Implemented Natures/Interfaces
* OffGridBatteryInverter
* ManagedSymmetricBatteryInverter
* ModbusComponent

*Description*: Reads machine state, battery voltage and signed battery current.
Active power is calculated from battery voltage and current. Stable mains and
inverter-powered states map to OpenEMS on-grid and off-grid modes. Startup,
transition, stopped, fault and unknown states intentionally report an undefined
grid mode. State `2` (`running (mains/bypass)`) is validated on the live unit;
the remaining state labels still require live transition testing.

*Guarded settings + schedule writes*: an opt-in path (`controlEnabled`, default
off) writes a fixed allow-list of SRNE settings registers - SoC thresholds and
charge-current limits, plus the time-of-use charge/discharge SCHEDULE windows for
TOU arbitrage. Each write is one-shot and readback-verified, and only fires while
the machine state is a live-validated running state; every target defaults to
`-1` (leave unchanged). Scalar settings use `SafeWriteHandler`.

A schedule window is a coherent unit handled by `ScheduleWindow`, governed by one
invariant: the enable register must read `0` on the device whenever the window
registers are written. The contiguous start/stop time pair (`0xE026/E027` charge,
`0xE02D/E02E` discharge, encoded `hour*256+min`) is written as a single atomic
FC16 block and read-back verified. A currently-armed window is never mutated in
place: any window change is sequenced disarm -> verify-disabled -> atomic window
write -> verify-window -> re-arm. The enable flag (`0xE02C` charge, `0xE033`
discharge) is the last step; the desired end-enable is captured once, so leaving
enable unmanaged (`-1`) on an armed device disarms, rewrites and restores the
armed state rather than mutating or silently disabling it. Any validation
failure, execute error or read-back mismatch leaves the enable flag untouched, so
a mis-set window can never leave a schedule armed (disabled is the safe resting
state).

Two operational notes: (1) if the control gate closes (machine state leaves the
verified running state, or `controlEnabled` is turned off) after a window change
has disarmed but before it re-arms, the discharge schedule stays disabled until
control resumes and the sequence self-heals - a transient loss of peak-shaving,
not a backup-safety loss (backup is governed by the SoC thresholds, not the
schedule). (2) As with the scalar settings writes, a stale pre-write read-back can
latch `SAFE_WRITE_STATE=FAILED` on a schedule that is in fact correctly armed;
FAILED here can mean "armed-but-unconfirmed" - re-read the registers to confirm. Start and
stop must be configured together; the window is validated as a within-day window
(both valid times, `start < stop`). Cross-midnight windows are rejected because
the SRNE has no defined midnight wrap and cannot encode 24:00 - a window that runs
to midnight must stop at `23:59` (5947). The inverter real-time clock (`0xE034-036`)
is exposed read-only so commissioning can verify the clock before any schedule is
enabled; a wrong clock fires every window at the wrong wall-clock time.

.*Configuration*:
* `id` (String): Unique component ID (default: `batteryInverter0`)
* `alias` (String): Human-readable component name
* `enabled` (boolean): Enables the component (default: `true`)
* `startStop` (enum): Start/stop behaviour (default: `AUTO`)
* `modbus_id` (String): Modbus bridge component ID (default: `modbus0`)
* `modbusUnitId` (int): Device Unit-ID (default: `1`)
* `maxApparentPower` (int): Maximum inverter apparent power in VA (default: `12000`)
* `controlEnabled` (boolean): Safety gate for FC16 settings/schedule writes (default: `false`)
* settings targets (int, `-1` = leave unchanged): `dischargeCutoffSoc`, `stopChargeCurrent`, `stopChargeSoc`, `lowSocAlarm`, `switchToLineSoc`, `switchToBatterySoc`, `acChargeCurrentLimit`, `maxChargeCurrentLimit`
* source-transfer targets (int, `-1` = leave unchanged): `outputPriority` (E204, source-priority mode e.g. SBU; range `0..3`) and `bmsCommunication` (E215, BMS-comms enable; range `0..2`). These enable "switch to battery at a SoC" (SBU + BMS-SoC) fully from OpenEMS. `outputPriority` is the output/source priority, distinct from charge priority. Two safety points: (1) `outputPriority` = SBU transfers the load onto the battery, so it is reconciled together with its reserve band (`switchToLineSoc`/`switchToBatterySoc`) and BMS mode (`bmsCommunication`) as ONE coherent, validated operation. When an arm is requested the whole set is validated - all three present, individually in range, and the band coherent (`switchToLineSoc` below `switchToBatterySoc`) - BEFORE any of them is written; on failure NOTHING is written (not the band, not BMS, not `E204`) and the operation reports terminal FAILED, so a rejected arm can never leave a bad reserve band on a unit already in SBU mode. Once the set is valid, `E204` arms only after each prerequisite is settled: its handler at rest (IDLE = already correct, or VERIFIED) AND the device currently reads the configured value - a queued, awaiting or failed write, or a post-verify drift, never counts as settled. When no arm is requested, BMS remains an independent setting; the reserve band is still refused if both thresholds are configured but inverted (`switchToLineSoc` at or above `switchToBatterySoc`), because a bad band is dangerous whenever the unit is in SBU (its normal backup posture, settable from the panel) - so an incoherent band is never written regardless of whether OpenEMS armed it. (2) The exact value-to-mode mapping (which number is SBU, etc.) is NOT verified in the SRNE manuals and MUST be captured on the unit at commissioning; the ranges here are bounded only, read-back verify guards a mis-accepted value, and a wrong-but-in-range value is prevented only by keeping targets `-1` until the enum is confirmed.
* TOU schedule windows (int, encoded `hour*256+min`, `-1` = leave unchanged): `chargeWindow1Start`, `chargeWindow1Stop`, `dischargeWindow1Start`, `dischargeWindow1Stop`. Start and stop must be set together; end-of-day is `23:59` (5947).
* TOU schedule enables (int `0`/`1`, `-1` = leave unchanged): `chargeScheduleEnable`, `dischargeScheduleEnable`. Written last, only after the matching window verifies; `enable=1` requires a configured window.

=== SRNE Grid-Meter

*Name*: SRNE Grid-Meter

*Factory-PID*: `Srne.Grid-Meter`

.Implemented Natures/Interfaces
* ElectricityMeter
* ModbusComponent

*Description*: Reads grid-input voltage for L1, L2 and L3, current for L1 and
grid frequency. The device does not expose grid current for L2 or L3 in the
validated register range.

.*Configuration*:
* `id` (String): Unique component ID (default: `meter0`)
* `alias` (String): Human-readable component name
* `enabled` (boolean): Enables the component (default: `true`)
* `modbus_id` (String): Modbus bridge component ID (default: `modbus0`)
* `modbusUnitId` (int): Device Unit-ID (default: `1`)

=== SRNE Backup-Meter

*Name*: SRNE Backup-Meter

*Factory-PID*: `Srne.Backup-Meter`

.Implemented Natures/Interfaces
* ElectricityMeter
* ModbusComponent

*Description*: Reads backup-output voltage, current and active power for L1, L2
and L3, plus backup-output frequency and reactive power. Reactive power for L1
is calculated from its apparent and active power registers. It is exposed as a
metered-consumption meter.

* `alias` (String): Human-readable component name
* `enabled` (boolean): Enables the component (default: `true`)
* `modbus_id` (String): Modbus bridge component ID (default: `modbus0`)
* `modbusUnitId` (int): Device Unit-ID (default: `1`)
